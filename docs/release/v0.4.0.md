# OfferFlow v0.4.0 Release Notes

发布日期：待定

## 版本定位

v0.4.0 定位为：

```txt
本地服务化与 SQLite 数据文件化
```

一句话目标：

```txt
把 OfferFlow 从 localStorage 手账，升级成一个真正可长期保存、可备份、可迁移、可恢复的本地求职数据仓库。
```

## 主要能力

1. **Tauri 桌面运行时**
   - 在保持 Web 模式可运行的前提下，引入 Tauri 桌面壳。
   - 桌面模式用于访问本机 app data 目录和 SQLite 文件。

2. **SQLite 本地数据库文件**
   - 新增 `app_meta`、`profiles`、`jobs`、`migration_logs`、`backup_logs`。
   - 采用“核心索引字段独立列 + 完整对象 `data_json`”方案。
   - schema version 写入 `app_meta.schema_version=1`。

3. **localStorage JSON 备份**
   - 迁移前生成 JSON 备份文件。
   - 备份记录写入 `backup_logs`。
   - checksum 使用 SHA-256。

4. **localStorage -> SQLite 迁移**
   - profile / jobs / AI 原文 / 解析结果 / 沟通状态 / v0.3 跟进事实字段进入迁移 payload。
   - 迁移写入 SQLite 后进行数量和关键字段校验。
   - 成功后写入 `migration_logs` 和 `app_meta.migration_status=migrated`。
   - 旧 localStorage 不删除，只写 done 标记作为已迁移提示。

5. **失败回滚与迁移校验**
   - profile/job 写入和成功日志位于同一 SQLite transaction。
   - 备份失败、profile 写入失败、job 中途失败、校验失败、坏数据、namespace 冲突、重复迁移、done 标记失败均有自测覆盖。
   - 默认拒绝重复迁移，返回 `already_migrated`，不覆盖既有 SQLite 数据。

6. **backend 受控切换**
   - Web 模式默认并继续使用 localStorage。
   - Tauri 模式也不会自动切 SQLite。
   - 只有显式 `offerflow:storage:backend=sqlite` 且 SQLite 中 `migration_status=migrated` 时，才判定 `sqlite_active`。
   - 失败时回退 localStorage。

7. **桌面端迁移确认入口**
   - 配置页底部新增“本地数据存储”面板。
   - 展示运行环境、当前 backend、SQLite 状态、localStorage profile/job 概览。
   - Web 模式不显示可执行迁移按钮。
   - Tauri 模式必须用户点击并通过二次确认后才执行备份 + 迁移。

## 仍然不做

v0.4.0 只改变本地存储底座，仍然不做：

1. AI API
2. BYOK
3. 云同步
4. 账号登录
5. 多端同步
6. 自动投递
7. Boss 自动化
8. SaaS 后台
9. 远程数据库
10. 浏览器插件
11. 爬虫

## 数据安全说明

1. 迁移前自动生成 localStorage JSON 备份。
2. 迁移失败时 SQLite transaction 回滚。
3. 旧 localStorage 数据不会被删除。
4. 迁移成功后也只标记已迁移，不清理旧 key。
5. OfferFlow 增强本地持久化、备份和恢复能力，但不承诺“永不丢失”。
6. 用户仍应保留重要备份文件。

## 已知限制

1. SQLite 仅桌面模式可用。
2. Web 模式仍使用 localStorage。
3. 暂无恢复 UI。
4. 暂无云同步。
5. 仍需用户手动确认迁移。
6. 当前 SQLite 文件名沿用 T3 落地结果：`offerflow-t3.sqlite3`。如需改为 `offerflow.sqlite3`，应单独设计兼容迁移。
7. T10 在 Codex 环境中无法同时满足“AppData 写权限”和“可见 GUI 点击”两个条件，最终 tag 前建议用户补跑一次可见桌面手动验收。
