# OfferFlow v0.4 封版前决策简报

> 本文记录 v0.4 封版（sealing）前关于"是否在封版前把浏览器真实数据导入桌面 SQLite"的决策过程与最终裁定。
> 性质：决策记录。范围：仅影响 v0.4 封版口径，不改动已实现的存储/迁移逻辑。

## 1. 项目背景

- OfferFlow 是一个**本地优先的求职手账工具**（Vue 3 + Vite + TypeScript），帮用户记录岗位、简历、求职偏好。原则：不接 AI API、不做后端账号、不做云同步。
- 用户原始诉求：数据"**存成本地文件，只要文件在，数据就一直在，避免丢失**"。
- 用户最初设想方案：本地服务端模块 + 文件持久化 + 前端调接口读取。

## 2. 现状

- **当前线上用的是 Web 版**：数据存在**浏览器 localStorage** 里（浏览器网页无权限写磁盘文件，做不出"本地数据库文件"）。
- 为实现"本地数据库文件"，v0.4 做成了**桌面端（Tauri）+ 本地 SQLite 文件**。代码全部完成（T1–T10），已提交在分支 `feature/v0.4-local-sqlite-storage`，比 `main` 领先，**尚未合并、未打 tag、未推 GitHub**。
- 自动化验证全过（迁移单元测试、typecheck、build、cargo test），桌面端启动 smoke 真实写入了本地 SQLite 文件。
- **唯一没完成的验收**："在可见桌面窗口里人工点一遍迁移流程"——因自动化工具无法驱动该 dev 窗口、用户操作时也觉得繁琐，这一步未做（但核心逻辑已被自动化测试与启动 smoke 覆盖）。
- **用户的数据已安全**：已用脚本把浏览器 localStorage 全部导出成 JSON 文件落盘。

## 3. 关键技术事实（影响决策）

- 浏览器 localStorage 与 桌面端 WebView 的 localStorage 是**两套互相隔离的存储**，不共享。
- 因此桌面端的 SQLite 迁移**只能迁移桌面端自己那份数据，够不到浏览器里的真实数据**。
- v0.4 当初**明确把"导入/恢复 UI"列为"不做"**（范围之外）。

## 4. 冲突点 / 待决策

封版前，要不要先把浏览器里的真实数据导入到桌面端 SQLite？

## 5. 方案

- **方案 A（直接封版，不导入）**：文档如实定稿 → 合并 main → 打 `v0.4.0` 本地标签（暂不 push）。数据已在 JSON 里安全，以后想用桌面版时再导。
- **方案 B（先一次性手动搬数据再封版）**：用桌面端开发者控制台，把导出的 JSON 写进桌面端 localStorage，再点迁移 → 进 SQLite。不改代码，但需用户手动操作控制台。
- **方案 C（给 v0.4 正式加"导入功能"再封版）**：扩大 v0.4 范围，新增导入/恢复入口，改 decision-log，需额外开发与测试。

## 6. 风险

- **导入的实际价值有限**：桌面端数据库与浏览器数据是两套；若用户日常仍用浏览器版，导过去的只是**一份"冻结快照"**，之后不会同步，久了会与真实数据脱节。
- **方案 C 会再次拉长工期**，与"尽快收尾"目标相悖，且违背 v0.4 原定范围。
- 方案 A 的唯一"瑕疵"：桌面端 SQLite 里暂时没有真实业务数据（只有测试 / smoke 数据），但能力本身已完整。

## 7. 最终裁定

**采纳方案 A：直接封版，不在 v0.4 封版前把浏览器真实 localStorage 数据导入桌面 SQLite。**

- **不选择方案 B**：不通过开发者控制台做一次性手动搬运。
- **不选择方案 C**：不在 v0.4 追加导入 / 恢复 UI。

裁定理由：

1. 浏览器 localStorage 与 Tauri WebView localStorage 隔离，当前导入只是一份**冻结快照**，不会形成长期同步。
2. v0.4 的封版目标是**本地 SQLite 能力完成**，而不是完成真实数据迁入。
3. 用户真实浏览器数据已通过 **JSON 备份落盘**，数据安全优先级已满足。
4. 未来如果用户长期切换到桌面版，再**单独设计**"从 JSON 导入 / 恢复到 SQLite"的能力（独立立项，不在 v0.4）。

## 8. 封版口径（执行约束）

- v0.4 封版选择**方案 A**。
- **可见窗口人工点击验收仍建议在最终 push / tag 前，由用户在本机可见 Tauri 窗口补跑一次**（清单见 `desktop-e2e-acceptance.md` 第 6 节）。
- v0.4.0 **可以本地封版**（定稿文档 + 合并 main + 本地 tag），但**不建议在用户补完可见窗口验收前 push 到 GitHub / 打远程 tag**。
- **不承诺"永不丢失"**；用户仍应保留重要 JSON 备份。
- v0.4 不新增导入 UI、不做恢复 UI、不做云同步、不做账号、不做 AI API。
