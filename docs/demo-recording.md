# OfferFlow Demo 素材生成说明

> 当前正式简历与面试表达材料以 `docs/resume-offerflow.md` 为准，本文档只服务于 Demo 素材录制流程，不重复维护简历/面试话术内容。

## 1. 目的

这份文档配套 `scripts/demo/capture-offerflow-demo.mjs`，用于自动生成一批用于**面试展示**的截图和录屏素材（关键页面截图 + 可选浏览器录屏）。

明确说明：这是面试素材准备脚本，**不代表生产级自动化测试**，不用于回归测试、CI 校验或质量门禁。它使用脱敏假数据驱动真实（或 mock）的页面交互，目的是留下一批可以直接用在面试、简历补充材料里的图像和视频。

## 2. 两种模式说明

- **real 模式（默认，推荐用于正式录屏）**：不拦截任何接口，走 OfferFlow 真实的前后端链路，包括真实调用 DeepSeek 的 SSE 流式分析接口 `/api/llm/analyze-job-stream`。这是最有说服力的素材来源，因为它证明项目真实跑通，不是摆拍。
- **mock 模式（兜底方案）**：用 Playwright 的 `page.route()` 拦截 SSE 接口，返回预先构造的模拟流式内容，不调用真实 DeepSeek。适用于：接口失败、没有网络、暂时没有配置 API Key、或者只是想快速生成一组稳定截图用于草稿排版。

**正式面试素材优先使用 real 模式，因为它更有说服力；mock 模式只作为兜底，不应冒充真实调用结果。** 如果最终用的是 mock 素材，讲述时要如实说明这是模拟的流式效果演示，不要说成是真实模型返回。

## 3. 运行前准备

1. 确认项目依赖里已经有 `@playwright/test`（脚本会自动检测，没有的话会提示安装命令，不会自动安装）。如需安装，先经过你确认再手动执行：
   ```
   npm i -D @playwright/test
   npx playwright install chromium
   ```
2. 启动本地 dev server（另开一个终端窗口，保持运行）：
   ```
   npm.cmd run dev
   ```
   默认会在 `http://localhost:5173` 提供前端页面，后端 API 监听在 `127.0.0.1:17365`。
3. real 模式下，确认本地 LLM 配置已经存在（脚本只会判断是否配置，不会打印任何密钥或环境变量的具体值）：
   - 项目根目录是否有 `.env` 文件
   - 是否设置了 `OFFERFLOW_LLM_API_KEY`（或 `DEEPSEEK_API_KEY`）等相关变量
   - 如果不确定，可以先跑一次 real 模式，脚本会在缺少配置时给出清晰提示，不会静默失败。
4. real 模式正式运行：
   ```
   node scripts/demo/capture-offerflow-demo.mjs --mode real --allow-demo-write
   ```
5. mock 模式兜底运行：
   ```
   node scripts/demo/capture-offerflow-demo.mjs --mode mock --allow-demo-write
   ```
   **不带 `--allow-demo-write` 时，脚本会在「保存岗位」这一步之前停止，以保护当前数据源**，只会留下前两张截图（首页、JD 录入），不会继续往下走。详见第 9 节。
6. 输出目录：每次运行会在 `artifacts/offerflow-demo/` 下生成一个带时间戳的子目录（例如 `artifacts/offerflow-demo/20260709-153000-real/`），避免覆盖旧素材。截图和录屏都在这个子目录里。

## 4. 生成内容

每次运行会生成：

- 多张关键页面截图（首页、JD 录入、流式分析中、分析结果、人工确认、决策面板），文件名带序号，mock 模式的文件名会额外标注 `mock`（例如 `03-mock-sse-streaming.png`）。
- 如果 Playwright 支持录屏，会生成一份浏览器录屏视频：real 模式命名为 `offerflow-real-demo.webm`，mock 模式命名为 `offerflow-mock-demo.webm`。
- 全程使用脱敏假数据（假公司「云杉智能科技 DEMO + 时间戳」、假岗位「AI 应用前端工程师 Demo」），JD 文本开头也带有 DEMO 标识，不涉及任何真实公司或真实求职信息。
- real 模式会真实调用 DeepSeek，走真实 SSE 流式分析链路；mock 模式完全不调用真实 DeepSeek，接口层面被拦截替换。

## 5. 推荐录屏讲解顺序

如果要基于生成的素材做一段正式录屏讲解，建议按下面 5 个镜头组织内容：

1. **JD 录入** —— 展示如何粘贴脱敏 JD、填写假公司和假岗位信息。
2. **真实 SSE 流式分析** —— 点击分析按钮后，展示内容如何一边生成一边显示（打字机效果），强调这是真实调用 DeepSeek 的流式返回，不是等待后一次性显示。
3. **OFFER_FLOW_JSON / 结构化输出** —— 展示分析结果里同时包含人看的 Markdown 报告和机器可解析的结构化数据，说明这是约束 AI 输出格式换来的结果。
4. **pending_review 人工确认** —— 展示 AI 分析结果不会自动生效，而是先进入待确认状态，需要人工点击确认/暂缓/拒绝。
5. **deriveDecision 决策建议** —— 展示确认之后，跟进决策面板如何根据当前事实状态（沟通进度等）派生出策略、下一步动作和止损建议。

## 6. 60 秒口播稿

> 这里用的是一段脱敏后的 JD，公司名和岗位名都是虚构的，不是真实招聘信息。现在点一下分析按钮，可以看到内容是一边生成一边显示的，这段走的是真实的 DeepSeek 流式调用，不是提前录好的动画。分析完之后，AI 的结果不会自动生效，它会先进入一个叫 pending_review 的待确认状态，我需要自己看一遍，选择确认、暂缓或者拒绝，只有确认过的才会真正进入后续流程。确认之后，可以看到下面这个决策面板，它是用一个叫 deriveDecision 的纯函数，根据当前岗位的沟通进度这些事实状态，实时算出建议的跟进策略和下一步动作，这一步完全不需要人工手动判断，但最终要不要照着做，还是我自己来决定。

## 7. 常见失败原因

- dev server 没启动，或者启动了但端口不是 5173。
- Vite 端口和脚本里假设的端口不一致（可以用环境变量 `OFFERFLOW_DEMO_WEB_URL` 覆盖）。
- 页面文案发生变化，导致按钮/输入框的文本选择器找不到对应元素。
- 项目还没有安装 Playwright（脚本会提示安装命令，不会自动安装）。
- real 模式下 API Key 未配置，或者配置了但值不正确。
- DeepSeek 接口超时或者响应异常（网络问题、服务侧限流等）。
- SSE 返回格式如果未来发生变化（比如 `data: xxx` 协议调整），mock 模式的模拟数据需要同步更新。
- 网络问题导致真实调用失败——这种情况下建议直接切换到 mock 模式，或者使用之前已经生成好的素材作为兜底。

以下方向明确不是当前优先级，仅作为未来可能的增强记录：

## 9. 数据写入边界与 DEMO 标识

- 脚本为了走真实 UI 流程（保存岗位 → 触发分析 → 人工确认 → 决策面板），需要在「保存岗位」这一步真实点击保存按钮，这会在当前 OfferFlow 本地数据源里写入一条脱敏 demo opportunity。
- 因此脚本默认**不允许静默保存**：必须显式传入 `--allow-demo-write`，脚本才会在保存这一步继续往下走；不传的话，脚本会在保存前停止，只留下首页和 JD 录入两张截图，不会产生任何数据写入。
- demo 公司名和岗位名会带明显的 DEMO 标识和时间戳（例如「云杉智能科技 DEMO 20260709-153000」/「AI 应用前端工程师 Demo」），JD 文本开头也会标注「DEMO 脱敏样本，用于 OfferFlow 面试录屏，不代表真实招聘信息」，避免和真实机会混淆。
- 录制完成后，如果这条数据进入了持久化数据源，需要自己到 OfferFlow 页面手动删除，或者直接忽略这条带 DEMO 标识的记录——脚本不会自动清理，也不会主动调用删除接口。
- 这条数据不是正式 opportunity，不用于真实投递、不用于真实跟进决策，只是为了触发真实 UI 和真实 SSE 分析链路而产生的过程数据。
- 如果不想在当前数据源里产生任何数据，可以暂时不跑脚本，改用手动录屏，或者等后续做 Public Demo Mode（沙箱数据源）时再考虑自动化录制。

运行命令（正式）：

```
node scripts/demo/capture-offerflow-demo.mjs --mode real --allow-demo-write
node scripts/demo/capture-offerflow-demo.mjs --mode mock --allow-demo-write
```

不带 `--allow-demo-write` 时，脚本会在保存岗位前停止，以保护当前数据源。
